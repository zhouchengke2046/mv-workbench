# 统一提醒（报警）格式与代码表

> 所有失败/阻塞/警告都走 `scripts/alerts.py` 的 `emit()`，输出一个**可直接转发**的提醒块。  
> 学生遇到问题：**把整块提醒原文发给老师**（长按复制），不要只说“报错了”，也不要把 Key 发出来——提醒块本身已脱敏。  
> 老师按 `代码 + 平台 + 错误类别` 快速定位，再决定怎么处理（修配置 / 发备用 `zz-keys.json` / 指导重跑）。

## 格式

```text
[提醒] <代码> <标题> | 级别=阻塞|提示 | 时间=YYYY-MM-DD HH:MM
平台=<router|runninghub|apimart> 模型=<model> 错误类别=<class> <统计>
已做自检：<agent 已经跑过的检查>
原始报错（≤300字）：<脱敏后的原文>
学生动作：<学生现在该做什么>
需要老师：<老师需要判断/提供什么>
```

规则：

- `级别=阻塞` 表示流程已停；`级别=提示` 表示仍在继续，但需要留意。
- `原始报错` 统一截断 300 字并脱敏（Key 不会出现）。
- 同一问题 agent 只发**一次**提醒，不会刷屏；重试/切换的过程写在 `已做自检` 里。
- 学生**不要**重复提交任务来“试试看”。

## 代码表

### Key / 配置（K）

| 代码 | 标题 | 学生动作 | 老师动作 |
|---|---|---|---|
| K001 | Key 未配置 | 导入老师发的 `zz-keys.json`（项目根目录/下载目录），或在工作台“配置 Key”里填写 | 确认是否已发放 / 发新的对应平台 Key |
| K002 | keys.json 读取失败 | 把提醒发给老师；不要自己改文件 | 指导修复或重发 `zz-keys.json` |
| K003 | Key 文件格式不对 | 把提醒发给老师；保留原文件不要删 | 核对文件内容/格式，必要时重发 |
| K004 | 找不到 Key 文件 | 确认 `zz-keys.json` 实际位置，把路径告诉 agent | 确认学生是否已收到文件 |
| K005 | 监听超时未收到 Key 文件 | 确认下载是否完成、在哪个目录；把路径告诉 agent | 一般无需处理 |
| K006 | agent 环境无法交互输入 Key | 双击 `setup-keys` 自己输入，或导入 `zz-keys.json` | 一般无需处理 |
| K007 | keys.json 权限不对 | Windows 可忽略；其它系统发给老师 | 确认系统/权限差异 |

### 备用 Key（B）

| 代码 | 标题 | 学生动作 | 老师动作 |
|---|---|---|---|
| B001 | Router 连续失败，备用 Key 未配置 | **把提醒原文完整发给老师**，等老师处理；不要重复提交 | 判断是否发放备用 `zz-keys.json`（含 `runninghub`/`apimart` 字段）或其它处理 |

> B001 就是“申请备用 Key”的标准方式：学生只负责转发提醒原文，发不发、发哪家的 Key 由老师决定。

### 平台调用（P，平台字段区分 router / runninghub / apimart）

| 代码 | 标题 | 典型场景 | 老师动作 |
|---|---|---|---|
| P1 | 平台身份/权限失败 | Key 无效、账号不存在、无权限 | 核对 Key/账号；必要时换 Key |
| P2 | 平台余额/额度不足 | 付费积分不足、余额不足 | 充值或发放新 Key |
| P3 | 任务提交失败 | 参数错、应用/工作流 ID 错、接口拒绝 | 按错误类别定位 |
| P4 | 平台任务失败 | 任务 FAILED / CANCELLED | 判断平台问题还是提示词/参数问题 |
| P5 | 平台超时/网络异常 | HTTP 5xx、URLError、轮询超时 | 确认平台可用性 |
| P6 | 产物下载失败 | 文件拉不下来 | 提供产物链接或指导补拉 |

### 工作台 / 数据（W）

| 代码 | 标题 | 学生动作 | 老师动作 |
|---|---|---|---|
| W1 | 工作台引用文件缺失 | 让 agent 先修复路径或重新生成 | 确认缺失清单 |
| W2 | DATA 不是合法 JSON | 不要手改 `data.json`，发给老师 | 指导修复或回退版本 |
| W3 | 工作台构建失败 | 发给老师 | 按报错定位模板/数据问题 |
| W4 | 页面比数据旧 | 让 agent 重建后强刷（Cmd/Ctrl+Shift+R） | 一般无需处理 |

### 时间轴 / 时长（T）

| 代码 | 标题 | 学生动作 | 老师动作 |
|---|---|---|---|
| T1 | 音乐时长与目标偏差过大 | 在「接受实际 / 重做音乐 / 后期裁」里选一个 | 给出倾向性建议 |
| T2 | 时间轴与歌词不一致 | 发给老师 | 核对 lyric.json 与音频 |
| T3 | ffmpeg/ffprobe 缺失 | 让 agent 安装后重试 | 一般无需处理 |

### 质检（Q）

| 代码 | 标题 | 学生动作 | 老师动作 |
|---|---|---|---|
| Q1 | 资产质检失败 | 等 agent 重跑一次；仍失败按提醒处理 | 给出改图意见 |
| Q2 | 资产质检警告 | 确认「用 / 不用」 | 给出建议 |
| Q3 | 视频段时长/规格不符 | 让 agent 重跑该段 | 确认规格要求 |

## 接入点（当前已接线）

- `mvwb keys`：K001–K007（含 import/watch/非交互）。
- `mvwb rh`（RunningHub）：P1–P6，`platform=runninghub`。
- `mvwb muse`（Router）：P1/P3/P4/P5/P6，`platform=router`。
- `mvwb check` / `mvwb build`：W1–W4。
- T/Q 类由 agent 按本表格式输出（暂未全部硬编码到脚本）。

## 示例

Router 连续失败、未配备用 Key（学生转发这块即可）：

```text
[提醒] B001 Router 连续失败，备用 Key 未配置 | 级别=阻塞 | 时间=2026-11-14 16:19
平台=router 模型=muse-video-ext 错误类别=timeout 连续失败=3/10min
已做自检：keys status ✓
原始报错（≤300字）：URLError: operation timed out
学生动作：把本提醒原文完整发给老师，等老师处理；期间不要重复提交任务
需要老师：判断是否发放备用 zz-keys.json（含 runninghub/apimart 字段）或其它处理
```

RunningHub 付费积分不足：

```text
[提醒] P2 平台余额/额度不足 | 级别=阻塞 | 时间=2026-11-14 16:30
平台=runninghub 模型=ace-step-1.5 错误类别=submit
原始报错（≤300字）：{"code":821,"errorMessage":"付费积分余额不足，消费级 API 调用仅支持使用付费积分"}
学生动作：把本提醒发给老师，并暂停生成
需要老师：充值或发放新 Key
```
