# 审核、版本与重跑

## 状态

| 值 | UI | 含义 |
|---|---|---|
| `not_started` | 灰环 | 未生成 |
| `draft` | 琥珀环 | 有产物待审 |
| `locked` | 绿环 | 已定稿 |
| `stale` | 橙环 | 上游改动，需重跑 |
| `failed` | 红环 | 失败 |

页面只显示环颜色，不显示状态文字；状态字段写 JSON/DATA 供 agent 判断。

## 版本

- 每次生成/重跑写 `*_v{n+1}.json` 和对应媒体，**不覆盖旧版**。
- `music[].current` / `segments[].videos[0]` 指向当前版本；历史保留。
- `spent` 累加历史成本；`cost` 是当前阶段成本。
- 模型/提示词/参考图/参数变更 = 新版本，不是原地改。

## 审核循环

1. 用户提出修改：只重跑点名项（一首歌/一张图/一个视频段）。
2. 更新对应 stage 的 `draft`，写新版本。
3. 用户确认后 `locked`。
4. 其他项逐字保留，不重跑。

## 上游变更

- 音乐 `locked` 后不可改；换音乐 = 新建 MV。
- 资产变更 → 依赖该资产的视频段 `stale`。
- 分镜/视频段计划变更 → 对应视频段 `stale`。
- 改原文 = 重新起工作台。

## 门

1. 原文确认
2. 批次参数（条数/时长/风格）
3. 框架审核
4. 生成范围 + Key/余额 + 报价
5. 内容审核
6. 交付（所有段 locked，写 handoff）
