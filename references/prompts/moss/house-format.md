# 房屋口径：图片提示词.md 格式契约

> 本文件是 MOSS 资产图提示词的格式真源；`scripts/check_image_prompts.py` 按此解析。
> 深配方（每段含义、文字政策、参考图边界）见 `moss.md` 与 `moss/examples/`。

## 1. 文档结构

```markdown
# 图片提示词 —— <项目>(vN)

> 依据/规格/状态说明（可含来源与目标）

## 角色板(16:9 · 三视图)
### IMG-C01 <名称>
**用途**:<一句话>
#### zh
```text
【用途】…【负面】…
```
#### en
```text
[Purpose] … [Negative] …
```

## 场景板(16:9 · 空镜 45° 俯视)
### IMG-S01 <名称>
（同上，zh/en 两块）

## 道具板(1:1 · 多视图)
### IMG-P01 <名称>
（同上，zh/en 两块）
```

- 一个 `### IMG-*` 下**必须恰好两个** ` ```text ` 块，顺序 zh → en；
- 允许在条目上方写"**用途**"中文说明（给人读），但它不替代正文里的【用途】段；
- 每 A 级标题下的分组决定该组强制项（见 §2）；id 前缀必须与分组一致。

## 2. 分组强制项（机检映射）

| 组 | id 前缀 | 画幅 | 正文必须出现 |
|---|---|---|---|
| 角色 | `IMG-C` | 16:9 | `三视图`（或"三格"）+ `面部特写` + `头部完全`（或"无头"）+ `背面` + `纯色`（或"无缝背景"） |
| 场景 | `IMG-S` | 16:9 | `无人`（或"空镜"）+ `大全景` + (`45°` 或 `俯视`/`俯拍`) |
| 道具 | `IMG-P` | 1:1 | (`多视图` 或 `正/侧` 或 "正视图…侧视图") + `纯色`（或"无缝背景"） |
| 细节/状态 | `IMG-D` | 1:1 | `特写`（或"微距"）+ 背景（`纯色` 或"虚化"均可）；**不做多视图** |

## 3. 段标签

每块（zh 与 en 各自）必须包含：`【用途】【画风】【版式】【背景】【文字政策】【负面】`；角色另加 `【身份锚点】【姿态】`，场景另加 `【地理锚点】【光线】`，道具另加 `【结构锚点】【光线】`（`【布光】` 与 `【光线】` 同义，二选一即可）。

- **【负面】四类**：版式误读 / 身份漂移 / 画质 / 文字。至少覆盖三类，且不含"颜色+形状"式点名清单（反回弹，见 SKILL.md）。
- 英文块用 `[Purpose] [Style] [Layout] [Anchors] [Pose] [Background] [Lighting] [Text policy] [Negative]` 对应段，机检只查块数与中文标签（英文标签不作为硬性门，但必须存在等价内容）。

## 4. 版式细则

### 角色三视图（16:9，单图三格）
- 横排三格、等宽、间距均匀；左=正面面部特写（头肩）、中=正面全身**头部完全不入画**（画面顶部从锁骨/领口以下开始，不出现脸、头发、脖颈断面）、右=背面全身。
- 三格同一人、同一服装、同一光照、同一背景色；比例一致、脚底对齐。
- 禁四视图、禁表情格、禁道具、禁故事镜头感。

### 道具多视图（1:1）
- 同一画布内并排正/侧（可加顶视或局部特写），一套光照，纯色干净背景；禁止手/人/环境；
- 多视图之间不得出现图注、引线、尺寸标注。

### 场景空镜（16:9）
- 无人（含无动物）、大全景、45° 俯视；固定锚点写相对关系（左右以前/中/后景参照，避免"左边"漂移）；
- 光向写明（自然光/月色/仪表光），与项目视觉设定一致。

## 5. 文件命名与落位

- 图片：`assets/IMG-<组><nn>-<名称>.png`；`名称`与 `data.js ASSETS[].name` 对应（文件名 slug 可简写，须在条目里注明对应关系）。
- `coding/assets.json` 由 `data.js` 的 ASSETS 编译，`file` 必须与磁盘逐字一致。

## 6. 提交前人工清单（checker 之外）

- [ ] zh 与 en 的事实逐项对齐（锚点/版式/负向/文字政策）
- [ ] 连续性锁两份都在
- [ ] 版式与分组一致（C=三视图、S=空镜 45°、P=多视图）
- [ ] 负向无"点名诱发"清单
- [ ] 提示词事实全部来自 `视觉设定.md`（不发明）
