# Muse Video（Router / TokenTech `muse-video-ext`）提示词与参考图规范

> 结论来自 2026-11-08 的 6 条实测 + Meta 官方 Muse Image 文档。Muse Video 是 Meta Superintelligence Labs 的预览模型（与 Muse Image 同底座），Meta 尚未发布视频版官方指南；以下是有依据的可用做法。

## 1. 模型事实

| 项 | 值 |
|---|---|
| 接口 | `POST https://router.kcacher.top/v1/videos` |
| 模型名 | `muse-video-ext` |
| 输出 | 720p（720×1280 竖屏）/ 24fps / H.264 + AAC，最长 10s；Router 支持 seconds（2s 已实测） |
| 参考图 | 最多 9 张，合计 ≤ 11MiB，URL / data URI / 裸 base64 |
| 比例 | 1:1、16:9、9:16、4:3、3:4、3:2、2:3 |
| 时长 | 固定最长 10s；Router 支持 seconds（2s 已实测），提示词里的"约 7 秒"基本无效，后期裁 |
| 价格 | 2s ≈ ¥1.00；10s ≈ ¥5.00（2026-11-13 实测） |

## 2. 提示词：写什么、写到多细

**结构（一段自然语言，不分节）**

1. 主体锚定：谁、哪张图、不可变特征（与参考图一致的写法）
2. 动作：一个主线动作，按时间顺序
3. 镜头：景别 + 是否运动（**运镜是负资产，建议写"固定机位"或干脆不写**）
4. 光线/环境
5. 声音：环境声 / 对白 / 音效（原生音频，写什么出什么）
6. 禁止项：不对口型、不看镜头、无字幕文字

**精度**：60–350 字。实测 59 字极简版与 250 字自然语言版都好于 722 字 H3 结构化模板。

**不要写**

- H3 的 `subject_definitions` / `retention_analysis` / `overall_soundscape` 等分节和元指令
- `[Shot 2] At 00:03.500` 这类分镜时间码（不控制时长，只稀释描述）
- 与参考图冲突的外貌描述（例：图里是长发，提示词写"披肩发" → 模型按文字出短发）
- `negative_prompt` / `seed` / 首尾帧 / 参考视频（接口不支持）

**要写**

- 参考图里已有的文字物件，点名"失焦虚化/无字"，否则会放大成乱码牌匾
- 声音（否则只有底噪，或无声音）

## 3. 参考图：怎么让模型知道谁是谁

- 接口没有命名机制，**按 `image_urls` 传入顺序读取**（Meta Muse Image 官方文档明确："they're read in the order you provide them, so you can caption each image inline"）。
- 固定顺序并在提示词开头逐条声明：

```
图1是女主角：……，五官、发型、服装必须与图1完全一致。
图2是场景：……，布局、光照、色调必须与图2一致。
图3是道具：……，外观与图3一致。
```

- 每张图只承担一个职责（人物 / 场景 / 道具），不要塞多张同类图让模型自己选。
- 不要写文件名（`role_nvzhu.png` 对模型无意义）。

**多视图设定图**：有效但有个前提——实测四视角设定图不会导致拼贴/分屏，人物在 10s 内最稳定；但它会**忠实复刻设定图里的那张脸**。如果设定图是二次生成的（本项目的 `role_nvzhu_sheet.png` 就是），会引入新的身份锚点，与原角色图漂移。优先用同一人的真实多角度照片；用生成设定图前先核对与原角色是否一致。

## 4. 实测对照（剧本2 G1 段，同一组素材）

| 版本 | 提示词 | 参考图 | 结果 |
|---|---|---|---|
| v1 | H3 模板 722 字 | 人物+场景 | 短发、换脸（文字与图冲突） |
| v2 | 自然语言 256 字 | 人物+场景 | 长发回来，脸接近 |
| e1 | 图1/图2 标注 313 字 | 人物+场景 | 良好，指代有效 |
| e2 | 只剩人物图 308 字 | 人物 | 良好，场景靠文字也成立 |
| e4 | 极简 59 字 | 人物+场景 | 最稳，脸最接近原图 |

## 5. 风格与色温（2026-11-08 实测）

**偏黄不是素材造成的**：`role_nvzhu.png` 黄度 -16.7、`scene_airport.png` -5.6、RunningHub G1 -5.1，而 Muse 默认出片 +1～+9。暖调是模型自身调色 + 提示词里"日间自然光/落地窗日光"共同造成的。

| 版本 | 风格写法 | 黄度 | 饱和 | 结果 |
|---|---|---|---|---|
| e4 | 无风格词（基线） | +4.9 | 5.4% | 自然，略暖 |
| s1 | 日韩治愈系 + 奶油色调 | +16.0 | 14.8% | 更黄更糊，发色变棕 |
| s2 | 再加"降低暖黄/冷白平衡" | -27.8 | 51.3% | 过冲到青蓝夜戏，翻车 |
| s3 | 英文韩剧/日剧治愈词 | +10.1 | 12.8% | 甜美但偏暖，头发变卷 |
| s4 | 只加"中性白平衡" | +2.9 | 4.9% | 最中性，但不甜 |
| s5 | 治愈系+奶油+中性白+锁直发 | +17.2 | 20.6% | 更黄更粉，变窗边静态 |
| s6 | 治愈系+阴天散射光 | -9.9 | 8.1% | 干净偏冷，动作丢失 |
| s7 | 治愈系+散射光+中性白+锁动作 | **-1.7** | 2.2% | 干净柔美，动作保留，推荐 |

**结论**

- "日韩爱情故事治愈系"能用，但它自带"暖黄+过曝+窗边逆光"的刻板印象，单加会更黄。
- 真正控色的是**灯光与白平衡词**："柔和散射自然光 / 阴天柔光 / 中性白平衡 / 低饱和奶油色调"。
- 不要写"降低暖黄色调""冷白平衡"这类负向强指令，会过冲到青蓝。
- 风格词会**改调度和造型**：容易把"快步走"变成"窗边静态肖像"、把直发变卷发/棕发。必须显式写"保持上述动作与跟拍，不要静止站姿""保持自然直发"。
- 16 段成片统一调色建议放后期 LUT；提示词只负责"不偏黄、不过曝、柔光"。

**推荐风格段（接在动作段之后）**

```
画面风格：日韩爱情故事治愈系，柔和散射自然光，中性白平衡，低饱和奶油色调，皮肤白皙通透，画面清新柔美。
保持上述动作与中景跟拍，不要改成静止站姿，不要望向窗外。发型保持自然直发。不要金色或黄绿色滤镜，不要整体偏黄，不要过曝。
```

## 6. “不要……”要不要写（2026-11-08 逐字节对照）

**结论：否定句基本无效，个别还会反效果；改用正面陈述。**

- s5 与 s8 的差别只有一组否定句（"不要卷发 / 不要金色或黄绿色滤镜 / 不要过曝"）和"浅粉"两字，其余相同。两条成片 **MD5 完全一致**（`407b13bf…`），即这些"不要"对结果零影响。
- s2 写"明显降低暖黄色调、避免偏黄偏橙"，结果过冲到青蓝夜戏（黄度 -27.8）。
- s7 把"保持上述快步行走的动作与中景跟拍"写成**独立一段的肯定句**，动作被锁住、色温也回到中性；s8 把"保持快步行走"塞在风格句尾，完全没有生效。

**规则**

1. 控色只写正面参数：光源（柔和散射自然光/阴天柔光）、白平衡（中性白平衡）、色调（低饱和奶油色调）。
2. 锁动作/发型用独立一段的"保持……"陈述句，不要写成"不要……"。
3. 文字类：写"背景指示牌失焦虚化"这种正面描述，比"不要出现文字"有效（仍不完美）。
4. "不对口型/无对白"这类否定句可以留，但别指望它起作用；真正的保障是动作设计里不安排说话。
5. 同一个有效 prompt 的产出是稳定的（不同 prompt 都能撞出逐字节相同结果），所以单条 A/B 可信。

## 7. 定位

- 适合：空镜、B-roll、情绪镜、草稿预演、廉价补拍
- 不适合：主角近景大特写、需要与既有成片严格同脸的镜头（用 H3/Seedance 那套）
